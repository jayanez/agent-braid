# VIS.1d Web Interface Guidelines audit (2026-11-05)

On 2026-11-05 the rendered viewer code (`index.html`, `style.css`, `loom.js`,
`timeline.js`, `planmap.js` and the 3D HUD in `braid-scene.js`) was reviewed against
the current Vercel Web Interface Guidelines (`command.md`, fetched that day). The
review ran on branch `feat/061-vis1d-explore`. SC-027 requires every finding to be
fixed or waived with a reason.

| Finding | Outcome |
|---|---|
| A governance marker or crossing in the loom is `role="button"` but has `tabindex="-1"` | **Waived.** Each lane row is a listbox option, and Left and Right on a focused row step through every element of that lane, crossings and markers included. Enter selects it. The events table is the complete keyboard alternative. A second roving group over the same marks would add a parallel focus path. |
| 3D labels are measured one at a time (layout thrash) | **Fixed.** A single pass shows all labels, reads all sizes, then hides them all. |
| 3D canvas has no keyboard way to choose an element | **Fixed in help.** The 3D help now says to select from the events table or the loom and press G to fly to it. G, F, the arrow keys and Esc work on the focused canvas. |
| Fly-to under reduced motion | **Pass.** `moveTo` jumps at once when `prefers-reduced-motion` matches. |
| No `theme-color` | **Fixed.** Light and dark `theme-color` metas match `--ground`. |
| "No events to show." is English only | **Fixed.** It now has a `data-i18n` key (`table.empty`, es and en). |
| The sticky table header covers rows when Tab moves upward | **Fixed.** `scroll-margin-top` is set on table rows. |
| `h1` and `h3` do not balance their wrapping | **Fixed.** `text-wrap: balance` is set. |
| The 3D help dialog scrolls the page behind it | **Fixed.** `overscroll-behavior: contain` is set. |
| Duration bars use `width`, not `transform` | **Waived.** At most 8 bars, redrawn once a second. `width` keeps the two stacked segments (running and waiting) laid out without extra math. |
| Every events table row is rebuilt on each refresh | **Waived for VIS.1d.** Rows use `content-visibility: auto`, and the store caps how many events are retained. Diffing the rows is a performance task, not a design one, and is noted for T074. |
| The pointer box is read on every pointer event; the width is read on every redraw | **Waived.** One read per event or redraw. No layout is written before the read. |
| The 3D HUD wraps over the canvas at 390 px | **Waived for VIS.1d.** The HUD stays readable (two rows). A compact preset menu is a candidate follow-up. |
| Every plan node is a tab stop | **Waived.** Plans hold at most a few dozen operations. Each node is named, and Enter or Space selects it. |
| `outline: none` on loom rows and plan nodes | **False positive.** `:focus-visible` replacements exist. |
| Clock text formatted by hand | **Waived.** These are elapsed times (`m:ss`) relative to the session start, not wall-clock times, so `Intl.DateTimeFormat` does not apply. |

The fixes landed in the T072 and T073 change. Before and after captures are in
`evidence/`.
