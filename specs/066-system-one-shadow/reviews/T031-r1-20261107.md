## Converge input resolved: REQ-003 scope (founder decision 4)

The 2026-11-01 converge input found that the code records an episode for a
report-bearing `analyze` result while REQ-003 named only `analyze-work`. Founder
decision 4 of 2026-11-07 ("Spec al código", PR #1151) chose to align the
specification with the code, with no behaviour change. This change amends REQ-003
and the S1.5a scope line in `spec.md`, plan item 2 and the scope line of `plan.md`,
both episode contracts, the REQ-003 and scope text in `assurance.json`, and one
inaccurate sentence of `docs/tooling/SYSTEM_ONE_SHADOW.md` (it called a
report-bearing `analyze` result "an AIM analysis"; the runtime `analyze` tool is
Git replay only and its result carries no report). A new test,
`ParityTests.test_report_bearing_analyze_result_records_one_aim_episode`, pins the
aligned behaviour: an `analyze` result that carries a report keeps envelope parity
and records one valid episode with operation `analyze` and kind `aim`. Negative
control (executed): with `analyze` removed from the operation set in
`ToolingService._shadow`, the test fails (`ValueError: not enough values to
unpack`); the code was restored afterwards and is unchanged in this change.
