# Plugin interface v0.2

`agent-braid plugin setup|discover|doctor|workspaces|serve` is additive. Setup accepts repeated source roots, previews exact user-registry/results effects and requires apply plus the matching preview digest. Removal changes only registration. Both hosts share AGENT_BRAID_HOME.

The user registry is `agent-braid-plugin-registry/v0.2` (0.1.0-alpha.3 onward). Its single global `telemetry` key (`off` or `local`, default `off`) is the persisted consent for plugin MCP local telemetry; it is changed only by `plugin setup --telemetry off|local` through the same preview/digest apply, never by skills or environment variables. Setup reads a v0.1 registry only to preview its migration to v0.2 (consent `off`); the migration keeps no v0.1 backup, earlier plugin versions refuse v0.2, and a rollback removes `registry.json` (results are kept) and registers again with setup. Until migration, MCP serves only bootstrap status `migration-required` with no workspaces.

The plugin MCP schema is agent-braid-plugin/v0.2 (0.1.0-alpha.4 onward): MCP prompts are removed, so the plugin publishes none and skills are the single invocation surface; v0.1 described the earlier surface that published three prompts. Tool names, resource URIs and the registry/telemetry statements here are unchanged. plugin-status and workspaces are read-only bootstrap tools. Delegated tooling calls require workspaceId; no caller root override is allowed. Each connection snapshots fixed-root services and telemetry consent; changes require reconnect. `plugin-status` and `plugin doctor` report configured and active telemetry modes, 30-day retention and no automatic upload without reading or creating metrics. With `local`, delegated workspace calls are recorded by the SPEC-047 collector as surface `mcp` under its unchanged data contract. Runtime tools exist only with explicit operator configuration and retain exact grants. Resources use agent-braid-plugin://<workspaceId>/... and remain service-owned. Core results are not rewritten.

Native managers own plugin files. Receipt-owned legacy uninstall remains the explicit migration mechanism. install.sh only invokes native managers at user scope, with explicit host/marketplace/ref and no sudo, Python provisioning or provider session.

Registry staleness (T016/T017, bounded defect fix; T014/T015 are not reopened). Any `plugin setup --apply` or `plugin workspaces --remove`, from any session or the CLI, can invalidate running connections. Staleness is judged on the effective configuration (telemetry consent plus normalized workspace rows), not raw document bytes or row order, so an idempotent re-apply does not require reconnect. A stale connection refuses delegated tools with status `refused` and `result: {"code": "reconnect-required"}` (the same code applies to resource reads, which raise a typed `RegistryStale`); `plugin-status` and `workspaces` still answer. `plugin-status` adds `reconnectRequired`, `baselineDigest` and `currentDigest`: 64-hex SHA-256 digests of the effective configuration at connection start and now, path-free. Reconnect the MCP with the host's native operation, then confirm equal digests. Immutable roots and grants per connection are unchanged. Telemetry of these refusals (T018, owner decision A): router-level refusals (reconnect-required, unknown workspace, malformed arguments, busy admission, full inventory) never reach the service telemetry boundary and are not counted; the SPEC-047 data contract is unchanged and no cause is recorded.

Registry quarantine (bounded defect fix after T016–T019, no new task; T014/T015 are not reopened). A registered worktree root that no longer exists is stale: it is excluded from the effective configuration, the configuration digest and the workspace service, and reported path-free as `staleWorktreeRoots` (`workspaceId`, `rootIndex`, `reason: "missing"`) by `plugin doctor`, `plugin workspaces` and `plugin-status`; it never invalidates the registry. A stale root that reappears changes the digest and yields `reconnect-required`; a deleted root alone keeps a running connection serving, because configuration that differs from the snapshot only by removed worktree roots has not grown. A workspace row that is unsafe (worktree root overlapping plugin state, symbolic link, non-absolute path, identity mismatch, unknown shape) is quarantined per workspace and reported as `unsafeWorkspaces` (`index`, `workspaceId` when well formed, `reason` naming the root index); other workspaces keep serving. Whole-registry structural problems and duplicate workspace ids remain fatal. `plugin doctor`, `plugin-status`, reconnect checks and setup's preview read the registry tolerantly. `plugin setup` refuses worktree roots that do not exist and adds `--prune-stale` (preview, then exact-digest apply) to remove stale roots and drop quarantined workspace registrations; without it setup keeps stale roots and refuses to rewrite a registry that holds unsafe rows.
