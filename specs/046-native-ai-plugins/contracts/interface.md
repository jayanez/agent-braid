# Plugin interface v0.1

`agent-braid plugin setup|discover|doctor|workspaces|serve` is additive. Setup accepts repeated source roots, previews exact user-registry/results effects and requires apply plus the matching preview digest. Removal changes only registration. Both hosts share AGENT_BRAID_HOME.

The user registry is `agent-braid-plugin-registry/v0.2` (0.1.0-alpha.3 onward). Its single global `telemetry` key (`off` or `local`, default `off`) is the persisted consent for plugin MCP local telemetry; it is changed only by `plugin setup --telemetry off|local` through the same preview/digest apply, never by skills or environment variables. Setup reads a v0.1 registry only to preview its migration to v0.2 (consent `off`); the migration keeps no v0.1 backup, earlier plugin versions refuse v0.2, and a rollback removes `registry.json` (results are kept) and registers again with setup. Until migration, MCP serves only bootstrap status `migration-required` with no workspaces.

The MCP schema is agent-braid-plugin/v0.1. plugin-status and workspaces are read-only bootstrap tools. Delegated tooling calls require workspaceId; no caller root override is allowed. Each connection snapshots fixed-root services and telemetry consent; changes require reconnect. `plugin-status` and `plugin doctor` report configured and active telemetry modes, 30-day retention and no automatic upload without reading or creating metrics. With `local`, delegated workspace calls are recorded by the SPEC-047 collector as surface `mcp` under its unchanged data contract. Runtime tools exist only with explicit operator configuration and retain exact grants. Resources use agent-braid-plugin://<workspaceId>/... and remain service-owned. Core results are not rewritten.

Native managers own plugin files. Receipt-owned legacy uninstall remains the explicit migration mechanism. install.sh only invokes native managers at user scope, with explicit host/marketplace/ref and no sudo, Python provisioning or provider session.
