# SPEC-075 T010 — owner decisions on canaries that pass the export (2026-11-16)

A probe before T010 (temporary home, real store ingest, real SPEC-074 adapter, real export) planted each plain-form
canary of the SPEC-074 corpus in a prompt, a response and a tool call. Token shapes, the bearer header, the private
key block and e-mail addresses were redacted. Four kinds passed into the dataset unchanged and were not flagged by
the SPEC-074 post-redaction scan: another user's home path (`/Users/<name>/`, `/home/<name>/`; SPEC-074 knows only
the current `$HOME`), a literal secret not passed at ingest, a free-text secret of unknown shape, and a raw attempt
id written inside content text (content, not the id field). The owner was asked two questions with options, risks
and undo; this record states the answers. It decides nothing else, makes no scientific claim, and changes no
SPEC-074 file.

| Question | Owner answer | Undo |
|---|---|---|
| Q1 another user's home path in exported bytes | **A.** Export-side refusal: any `/Users/<name>/` or `/home/<name>/` path in the final dataset or manifest bytes (or their decoded views) aborts the export with `canary-detected`, nothing written. Not B (export-side redaction), not C (SPEC-074 change, a possible later follow-up), not D (accept). | remove the export check (one function); no data changes |
| Q2 literal secrets not passed at ingest, and secrets of unknown shape | **A.** Accept as documented residual risk, as the SPEC-074 privacy review does; limits and docs say the export scan catches the SPEC-074 pattern classes, the current `$HOME` and other users' home paths, literal secrets only when passed at ingest, and no unknown shape. Not B (owner-supplied literal list at export), not C (ingest always receives the list). | documentation only |

`human_review` stays `pending`.
