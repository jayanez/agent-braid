## Admission and identity rules (VP-REQ-01)

All listed keys are required and exact at every object level; extra or absent keys refuse, including `confidence`, `calibratedProbability`, `verified`, callable/plugin paths and authority fields other than literal `executionAuthorization: false`. Root must be an object. Use the bounded parser rules of [stdlib-v1](stdlib-v1.md): inclusive raw/canonical 1,048,576 bytes, container depth 16, no BOM, duplicate members, trailing non-whitespace, non-finite numbers, invalid UTF-8 or surrogates; integers signed 64-bit after at most 20 digits. New wire records use integers only for counts/time budgets; booleans are not integers. Deep freeze validated containers; freeze is not a validation substitute. Invalid wire data produces a sanitized refusal, not an uncaught exception or a partial answer.

`ID` means nonempty string at most 64 UTF-8 bytes, no C0/C1 controls or surrogates, no normalization. `H` means 64 lowercase hex SHA-256 characters; `G` means 40 lowercase hex Git SHA-1 object ID, without claiming collision-proof authenticity. Zero G is absence only in the retained T024 change preimage/file-addition semantics; it is not an admissible base/source commit or expected native tree. Arrays preserve order. Object keys sort only in canonical serialization. Canonical bytes use `agent_braid.system_one.canonical`: sorted keys, separators comma/colon, UTF-8, ensure_ascii=False, allow_nan=False, no trailing newline, no Unicode normalization. This is the existing Python reference encoding, not a new cross-language numeric standard. `hash(x)` below is SHA-256 of those bytes. A self-digested record hashes all its fields except its one named digest field; do not hash a zero placeholder. Rehashing untrusted content never substitutes for comparison with independently reconstructed facts.

### Exact request

| Key | Type / constraint |
|---|---|
| format | literal `s1-verified-request-v1` |
| requestId | ID; binds this request, not a replay grant |
| source | exact `t022-ingress-v1` record defined below |
| interpretation | exact existing `t024-text-v1` record below |
| budgets | Budget record below, no defaults |
| executionAuthorization | literal false |

Request digest is `hash(request)`; raw-byte hash may be retained separately for audit, never confused with the canonical digest. Caller supplies a local repository explicitly within a coordinator-designated owned fixture root. Do not expand T024 acquisition to arbitrary repositories/private histories. Admission checks size/types/version/declared limits before Git or scratch allocation. Source acquisition precedes interpreting claims about that source.

`source` contains exactly `format`, `task`, `declaredEffects`, `executionAuthorization`; format is `t022-ingress-v1`, authorization false. `task` exactly `{request, goal, options, optionOrder}`. Its `request` exactly `{gitAnalysisRequestVersion, repository, baseRevision, operations}` with literal version `0.1.0-alpha`, explicit absolute local repository path, nonzero G base commit and 2–4 operation objects. Each operation exactly `{instanceId, attemptId, source, dependencies, uncertainPaths}`: instance IDs the complete set a/b[/c[/d]], attemptId ID, source exactly `{kind: "commit", revision: nonzero G}`, dependency array unique other instance IDs forming a DAG, uncertainPaths empty. Each source descends from base. Repository realpath must remain inside the owned root and carry `.owned-native-fixture`; marker alone conveys no authority. Reject links/escapes and unresolvable identities. This lane does not fetch remote URLs.

`task.goal` is a path-sorted array of exact `{path, blob: G}` covering all and only changed paths, unique. `options` is a mapping of exactly four distinct option IDs (`[a-z][a-z0-9]*`, bounded by ID), exactly one null defer option and three arrays of 0–6 instance IDs. `optionOrder` is a length-four permutation of those IDs; retain it explicitly because canonical object sorting cannot preserve insertion order. A repeated operation in a plan is a valid offered candidate that fails semantically; duplicate option IDs, cycles or invalid operation IDs refuse the request. `declaredEffects` is an instance-ID mapping to path-sorted arrays of exact `{path, before: G, after: G}`. Compare exactly to all observed changes; never merge a declaration into observed evidence.

`interpretation` exactly `{format, language, representation, text, executionAuthorization}`: `t024-text-v1`, language en/es, representation symbolic/controlled, false, and text <=65,536 UTF-8 bytes with terminal LF and 2–96 lines. Header and literal record tokens/order/round trip must match `eof_verification/language.py` exactly. JSON literal parsing must also enforce duplicate/finite/integer rules above; this is explicit ingress hardening, not an assertion that the old inner `json.loads` already enforced it. Restore the complete IR and compare its digest to the acquired IR. Unsupported prose, omitted records, altered goals or prefixes refuse, never guess.

## Acquired snapshot and retained IR (VP-REQ-02)

`AcquiredSnapshot` has exactly these keys:

| Key | Type / meaning |
|---|---|
| format | `s1-acquired-snapshot-v1` |
| sourceRequestDigest | H = hash(request.source) |
| snapshot | retained T024 observation record described below |
| snapshotDigest | H = hash(snapshot) |
| domainId | `t024-eof-context-v1` |
| irVersion | `t024-literal-program-v1` (new wrapper identity, not an old wire version) |
| irDigest | H = hash(program) |
| grammarVersion | `t024-text-v1` |
| observationContract | `t024-path-blob-projection-v1` (new explicit name for changed-path final blobs only) |
| bounds | exact Bound record below |
| program | exact retained T024 program below |
| observedEffects | same shape as declaredEffects, independently acquired |
| declaredEffects | exact copy from source |
| coverage | exact `{status: "complete", paths: [sorted unique changed paths], operations: [a,b[,c[,d]]]}` |
| executionAuthorization | false |

Snapshot exactly `{base, sources, operations, taskDigest, semanticVersion}`: base G, sources mapping of canonical operation ID to G, taskDigest=hash(task), semanticVersion=`t024-eof-context-v1`; operations mapping ID to exact `{source: G, dependencies: [IDs], changes: [...]}`. Each acquired change exactly `{path, old: G, new: G, oldLines: null|[lines], newLines: [lines], hunks: [...], patchSha256: H}`; patchSha256 hashes the raw acquired Git diff bytes, not a reconstructed patch. Hunks have the same exact fields and marker bytes as program hunks. Snapshot digest binds their full content. It retains the historical T024 snapshot meaning; the new outer format does not rename its inner fields or fabricate a stronger observation.

Program exactly `{files, goal, ops, plans}`, all mappings. `files`: 1–8 flat `[a-z0-9][a-z0-9.-]*\.txt` paths to null (absent) or LF lines; `goal`: same keys to G; `ops`: a/b[/c[/d]] to `{dependencies, changes}`; `plans`: the complete options mapping reconstructed in optionOrder for legacy comparison. Operation changes exactly `{path, old, new, hunks}` with 1–2 unique sorted paths. Hunk exactly `{begin, end, old, new, atStart, atEnd, patchLines}`: integer source coordinates (bool excluded), old null only for supported addition, new line array, exact booleans for source boundaries, 1–128 marker-prefixed patch lines. Prefixes are actual space/plus/minus diff bytes, never inferred from equal text. Reconstruct old from space/minus, new from space/plus, require an actual edit, exact source pre/post blobs and unique source anchors; no overlapping own hunks. File addition requires one whole-file hunk at 0/0 with both boundary flags true. A/M mode 100644 only; no deletion, rename, symlink, executable/binary/CRLF/NUL/no-newline or uncertain effects. Existing files and standalone source postimages obey the stricter source bounds below.

Bound record has exactly `{maxFiles:8, minOperations:2, maxOperations:4, maxPathsPerOperation:2, maxHunksPerPath:2, maxPatchLinesPerHunk:128, maxInitialLines:64, maxInitialBytes:4096, maxResultLines:128, maxResultBytes:8192, maxTextBytes:65536, maxTextLines:96, offeredOptions:4, maxPlanLength:6}`. Lines are nonempty non-whitespace strings, each one LF only; UTF-8; no CR/NUL. Each standalone operation source postimage is also <=64 lines/4096 bytes because T024 validates reconstructed source text with initial bounds; intermediate/final composed states may be <=128/8192. These fixed domain bounds describe support; caller resource budgets may tighten, never silently truncate or enlarge the domain. Hunk work, including source validation and every candidate/revalidation application, is shared across the outer request with caller cap 0–128. This new aggregate cap is deliberately stricter than legacy verify(hunk_budget), which counted offered-plan applications after source validation; legacy default64 is not an equivalent whole-path allowance or a missing-budget default in this lane.

## Verification, selection and unknown (VP-REQ-03)

Retain T024 literal application: each operation stages all its changed files and commits atomically in the abstract model only if every hunk applies uniquely. `atStart` requires runtime position0. If source `atEnd` is true, require runtime EOF **only when no trailing space-prefixed context line remains**. Retained trailing context allows the previously recovered append/reorder; terminal edits without it remain constrained. Never relax BOF, uniqueness, dependencies, postimage reconstruction or multifile atomicity. Run every non-null offered plan from the same initial files; no early success shortcut. Complete means each operation exactly once with dependencies met; final goal means all tracked changed-path blobs match. Observation excludes untracked files, arbitrary effects and global confluence. Native consumer must additionally check its complete expected tree.

`VerifierResult` exactly `{format, registryDigest, verifierDigest, snapshotDigest, irDigest, optionIds, plans, eligibleOptionIds, status, reasonCodes, executionAuthorization}`. Format `s1-verifier-result-v1`, all digests H (null only when unestablished on refused admission), optionIds exactly optionOrder, false. plans is an array in optionOrder excluding the null option, each exact `{optionId, valid, complete, goalAchieved, cost, failure, trace, finalBlobs}`. valid/complete/goalAchieved are actual booleans only after a completed finite simulation, cost integer0–6; failure null or exact `{step: integer0–6, reason: "operation-precondition"|"missing-context"|"file-already-exists"|"final-goal"}`. Trace <=6 entries exact `{operation, committed, fragments, blobsAfter}`; fragments are exact {path: supported path, hunk: integer0..1, position: integer0..127} objects bounded by the program. All finalBlobs/blobsAfter map the complete files set to G. Unknown is never encoded as false: if acquisition/verification cannot complete, status refused, plans=[], eligibleOptionIds=[], with a fixed reason; no semantic assertion is emitted. The defer option has no simulated plan record. No proxy labels, probabilities or calibration field exists.

Status is **answered**, **semantic-defer** or **refused**. Answered eligibleOptionIds are all valid plans with minimum operation count, sorted lexically by ASCII option ID, not all valid plans and not supplied insertion order. Selection picks its first member. Semantic-defer has eligibleOptionIds containing exactly the designated null option, representing no verified goal-reaching offered plan; complete negative plan evidence is retained. Refused has no eligible option and no choice, even if partial work previously found a success. This preserves T024 minimum-cost and lexical tie behavior. It corrects the earlier sketch's unspecified “stable option order”; changing policy requires a new ID and migration.

`VerifiedDecision` exactly `{format, requestId, requestDigest, snapshotDigest, irDigest, registryDigest, verifierDigest, policyDigest, optionSetDigest, eligibilityDigest, status, selectedOptionId, reasonCodes, evidenceRefs, usage, executionAuthorization}`. format `s1-verified-plan-v1`, all pins H, selectedOptionId the first eligible ID for answered, null for defer/refused; false. Null defer selection intentionally differs from T024/T025 `choice="wait"`; preserve the actual defer ID in bound verifier result. `optionSetDigest=hash({optionOrder, options})`; `eligibilityDigest=hash(VerifierResult)`; no self digest in decision. `policyDigest=hash({format:"s1-selection-policy-v1", cost:"operation-count", tieBreak:"ascii-option-id", requireComplete:true, executionAuthorization:false})`. Registry/verifier digests must be recomputed from coordinator-pinned allowlisted manifests/source bytes, never accepted from caller claims. evidenceRefs is an ordered array of at most16 exact `{kind: "snapshot"|"interpretation"|"verifier-result", digest: H}` containing exactly one of each kind, in that order. Consumer receives those complete bodies separately and checks each digest; hashes alone are not evidence availability. Refused pins not established are null; answered/defer require all pins and evidence. RequestId/digest are null only if request admission failed. Usage always present, with unknown fields null.

Reason codes are a nonempty unique sorted array for defer/refused; answered has []. The fixed taxonomy is: `invalid-envelope`, `unsupported-version`, `unsupported-domain`, `unsupported-observation`, `invalid-budget`, `input-budget-exceeded`, `source-unavailable`, `source-drift`, `unsupported-effect`, `incomplete-observation`, `declaration-mismatch`, `text-mismatch`, `invalid-ir`, `ambiguous-anchor`, `work-budget-exceeded`, `deadline-exceeded`, `cancelled`, `registry-mismatch`, `verifier-mismatch`, `no-goal-reaching-plan`, `evidence-mismatch`, `internal-failure`. Map old detailed exceptions through a fixed table at the boundary; never expose raw OS paths/stderr as codes. Detailed sanitized local diagnostics can reference an immutable receipt. Only semantic-defer uses `no-goal-reaching-plan`. A known false candidate is evidence, unknown domain/refusal is not a false result.

## Budget and resource semantics (VP-REQ-04)

Budget exactly `{decisionBudgetMs, acquisitionBudgetMs, prepareBudgetMs, stageBudgetMs, maxHunkApplications, maxGitCommands, maxOutputBytes, maxCommandOutputBytes, maxScratchBytes, terminationMode}`. All duration caps are explicit integers1..2,147,483,647; this is a representational range, **not a supported product latency range**. Counts/bytes integers: hunk0..128, Git1..512, output1..16,777,216, command output1..8,388,608 no larger than aggregate output, scratch1..67,108,864. These Git resource maxima propose the existing GitCommandBudget default envelope; they do not assert instantaneous scratch enforcement (sampling) or memory guarantees. Larger values refuse. No retries or budget reset. `terminationMode="cooperative"` only; any other value, including hard, returns refused with exactly `invalid-budget` at request admission in T05, before source or consumer work. A missing prepareBudgetMs also returns exactly `invalid-budget`; no consumer-only reason code is needed. Existing child-process kill/reap support is not universal filesystem/native-call termination.

stageBudgetMs exactly `{acquisition, interpretation, verification, selection, expectedTree, handoffRevalidation, nativeCheck, nativePrepare, transportEvidence, cleanup}` with positive duration caps. acquisition cap <=acquisitionBudgetMs; interpretation/verification/selection caps <=decisionBudgetMs; all caps <=prepareBudgetMs. Separate child stages may sum above the parent, because each consumes the remaining outer budget; they are maxima, not reservations. At outer consumer ingress capture one monotonic start and `outerEnd=start+prepareBudgetMs`; acquireEnd=min(outerEnd,acquireStart+acquisitionBudgetMs), decisionEnd=min(outerEnd,decisionStart+decisionBudgetMs); these enclosing ends are initialized once at first entry and reused for all repeated work in the same request; each stageEnd=min(enclosingEnd,stageStart+stageCap). Deadline equality is expired. Monotonic absolute timestamps are process-local and never serialized/restarted in another process. Transport keeps parent deadline locally and sends only remaining allowance to a child, while measuring/reaping it locally. New child allowance cannot exceed parent remaining time. Budget identity and spent counters stay in the trusted local context, not caller-resettable JSON. Multiple acquisitions/verifications share aggregate counters and outer deadline; each repeated invocation is also recorded. Reserve cleanup opportunity before entering the next stage, or refuse. Cleanup failure/overrun remains visible even if a response was already refused.

Decision boundary starts on entry to the pure decision phase after acquisition and includes interpretation, verification, selection and sealing. Acquisition and complete prepare each have their own reported duration. Admission/parsing/queueing occur within outer consumer budget, not an implicit reset. No hard wall bound is promised for blocking ingress/filesystem/cleanup; unsupported required guarantee refuses. Pure workers check cancellation/deadline at entry, bounded loops and before sealing; cancellation is monotonic and cannot be reset. Suppress late answered output. Hold ownership/admission until actual work stops; never label a lingering worker as cleaned. DDP-T06 must demonstrate enforceability and choose useful supported numeric budgets from full-stage evidence; that acceptance gate is open. The legacy classifier's <=5,000ms cap is unrelated and must not be transplanted here.

Usage exactly `{acquisitionNs, decisionNs, prepareNs, cleanupNs, entryToCleanupNs, stages, hunkApplications, gitCommands, outputBytes, peakScratchBytes, termination, cleanup}`. Durations/counts nonnegative signed64 or null; unmeasured is null, never zero. stages is an ordered bounded array (max64) of exact `{name: stage key, occurrence: integer0..63, elapsedNs: integer|null, outcome:"completed"|"refused"|"expired"|"cancelled"|"unknown"}`. Repeated verifier calls receive distinct occurrences. gitCommands counts attempted command admissions per existing GitCommandBudget.commands, including a refused attempt; actual spawned-child counts are separate local supporting evidence, never inferred equal to this counter. Independent durations are not summed with nested spans. termination is `not-started|stopped|unknown`; cleanup is `not-allocated|removed|failed|unknown`. This local receipt shape does not extend `s1-stage-observation-v1`, activate telemetry or persist private content. All native permission/admission, scientific, human and activation gates remain separate.

Cleanup is attempted for every allocation even after cancellation/outer expiry; cancellation forbids further semantic/native work and late answered publication, not release of owned resources. Cleanup has its explicit phase cap/reserved opportunity, never a fresh execution allowance. A blocking cleanup that outlives response/deadline is reported as failed/unknown with eventual entry-to-cleanup duration; admission/ownership remains held until actual work stops. No unsupported hard cleanup bound is claimed.

For the exact trusted in-process Git budget/remaining-time/cancellation seam and scratch ownership across repeated acquisition, see the [CT01 acquisition interface](../decision-delivery/addenda/ddp-t01-plan.md#trusted-acquisition-seam--ct01-disposition). Wire schemas above remain data only.
