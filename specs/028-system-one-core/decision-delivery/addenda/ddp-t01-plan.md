### Trusted acquisition seam — CT01 disposition

`limits` is exactly the fixed integer-valued Bound record from the decision contract, not a hidden context or extensible option bag. The additional Python parameters are internal injected dependencies, never serialized keys or callables accepted from wire input. `git_budget` is the **same object identity** across producer acquisition and every in-process handoff reacquisition. Coordinator/T05 creates it once from admitted ceilings with `temp_root` the coordinator-owned scratch parent, `started_at=outerStartNs/1e9`, `wall_seconds=prepareBudgetMs/1000`, explicit max_commands/max_output_bytes/max_command_output_bytes/max_scratch_bytes from request and a request-local monotonic `threading.Event` cancel_event (not None). No worker calls clear(), changes started_at, increases limits or resets commands/output/scratch accounting. Existing GitCommandBudget fields/signature are used; no new library parameters are presumed.

`remaining_ns(stage: str) -> int` returns max(0,min(original outer end, memoized enclosing acquisition/decision end, current phase end)-monotonic_ns()). Coordinator opens an invocation before calling B. The first acquisition sets acquisitionEnd once; later reacquisitions reuse that same end and aggregate counters, never start a new acquisition allowance. Each invocation's phase cap can tighten it, never extend the memoized enclosing end. `checkpoint` enforces that context and the cancel_event; `remaining_ns` exposes the remaining allowance needed by the existing Git API. Clock injection is coordinator-local for tests; no wire absolute timestamp crosses a process.

B checks checkpoint before each operation/child, obtains positive remaining_ns("acquisition"), then calls **existing** `run_git(cwd, args_tuple, env=sanitized_env, budget=git_budget, input_bytes=bytes_or_none, allow_failure=bool, command_timeout=min(30.0, remaining_ns/1e9))`. Consume the existing GitCommandResult.stdout/stderr/returncode and existing exception categories. The research helper's data/extra/check arguments are not parameters of run_git; port behavior explicitly rather than calling an imagined overload. GitCommandBudget retains command/output totals and cancel checks; source acquisition adds its phase cap without replacing that object. B never imports A/C or hides the shared budget in a global/contextvar.

Coordinator owns the parent scratch directory, cancellation event and final cleanup receipt until all work actually stops. B may create unique child directories under git_budget.temp_root and cleans its own children in finally; it cannot delete the parent or source repository. Producer and consumer reacquisitions use this same request-local object in one process and preserve totals even when a child directory is removed. Parent lifetime extends through T06 and cleanup. Across stdio, the object is not serialized/pickled or recreated as proof of parent accounting: parent keeps its trusted context, enforces remaining allowance and verifies complete child work counters/termination. Existing native APIs without this injection retain their own bounded contracts; T06 must demonstrate outer aggregate accounting/enforcement or refuse/leave acceptance pending, not claim they already share this Python object.

V32 requires two acquisitions sharing the object with max_commands=1: after the first one-command fixture read, a second run_git admission must raise GitCommandLimitExceeded and issue no second child.
