# Additive deterministic decision architecture

Feature-local proposal, not an adopted canonical architecture. No change to decision-stdlib-v1, its synthetic identities/state, question semantics, canonical serialization or strict default abstention. Keep the optional neural text profile and artifact-v1/v2 loader contracts separate. Public export requires migration review; initial extraction is internal and opt-in, with no default CLI/MCP registry change.

## Pipeline and responsibilities

1. **Typed contract** retains existing boolean/choice/score API. Introduce a separate `s1-verified-plan-v1` result for bounded plan admissibility: it is not a probability distribution or a synthetic `ruleAnswers` state. Consumers expecting decision-stdlib-v1 must reject it, rather than coerce it.
2. **Acquisition** takes an explicitly supplied pinned repository/base/source/patch request using existing local read-only primitives. Reads only allowlisted revisions and materializes owned scratch. It produces observed effects and a complete source binding; declarations remain distinguishable. No private histories, network, arbitrary paths, silent cropping or generated labels. Acquisition failure is technical refusal.
3. **Interpretation** accepts only exact T024 controlled/symbolic EN/ES syntax and validates canonical round trip against acquired facts. General prose is unsupported and refuses before selection. This is a replaceable interpreter boundary; a future learned interpreter cannot bypass source fidelity.
4. **IR** preserves actual diff line prefixes and reconstructs old/new blocks exactly. Pin initial domain `t024-eof-context-v1` and grammar `t024-text-v1`; extracted code must not silently redefine either. Add an explicit envelope binding IR bytes/version, source snapshot, goal, complete operations/dependencies, offered plans, observation contract and bounds. A future semantic change gets a new version and migration tests.
5. **Verifier registry** is static, immutable, allowlisted and digest pinned. Initial single domain is the bounded LF UTF-8 fixed-patch domain. No dynamic imports/callables, plugin paths or claimed universal verifier. Registry key binds domain + IR version + observation contract + verifier implementation digest. Unknown/mismatched combinations refuse. Generic integer/structured exchange domains can be added later only with their own contracts and controls; they are not part of the initial implementation.
6. **Selection/policy** consumes complete eligible-plan membership and consequences from the verifier. Select by a declared deterministic stable option order among verified goal-reaching plans, otherwise semantic-defer. Never turn admissibility into calibrated probability. Report tie/selection rule and all eligibility reasons. Existing strict probability policies remain unchanged. No neural input or ranking in this initial capability. A later learned priority may reorder only the verified eligible set, with separate authority/evidence; no training prerequisite for this useful path.
7. **Evidence** binds source, IR, grammar, verifier, policy, options, choice and consumer identities. Separate producer claim from consumer verification and from actual observed reference outcome. Unknown costs are null. Local deterministic correctness within an explicit finite domain is distinct from workload accuracy. Hashes establish byte linkage, not authenticity or permission.
8. **Consumers** re-acquire/rebind and reverify before preparing the exact selected request/tree. Preparation remains temporary and read-only; no persistent run, grant, execute/recover, promotion or policy activation. T025 supplies the EOF end-to-end integration reference; do not copy T022's old verifier/final-tree builder. Core API, ToolingService and actual stdio must agree on bytes, errors, cancellation and cleanup.

## Contract sketch for DDP-T01 to freeze

All envelopes are bounded data, deep immutable on admission. Reuse existing canonical JSON validation helpers without enlarging v1 limits. Proposed outer ceiling 1 MiB raw/canonical and depth 16, with the stricter T024 nested limits retained (text 65,536 bytes, <=96 lines; initial file <=64 lines/4,096 bytes, result <=128 lines/8,192 bytes; <=8 files, 2–4 operations, <=2 files/op, <=2 hunks/file). Coordinator must confirm every bound against current T024 validation before contract freeze; select the stricter value on conflict only through explicit review, never silent truncation. Separate decision, acquisition and complete native-prepare budgets are required; see latency-and-budgets.md. An enclosing absolute deadline includes its declared nested work and never resets per stage. The classifier deadline is not the prepare deadline; no infinite fallback.

`AcquiredSnapshot`: format, sourceRequestDigest, snapshotDigest, domainId, irVersion, irDigest, grammarVersion, observationContract, bounds, observedEffects, declaredEffects, coverage, executionAuthorization=false.

`VerifierResult`: format, registryDigest, verifierDigest, snapshotDigest, irDigest, complete ordered option IDs, per-option eligibility/consequence/reason records, status (verified/defer/refused), executionAuthorization=false. A verifier rejection is not a valid semantic-defer for malformed input.

`VerifiedDecision`: format=`s1-verified-plan-v1`, requestDigest, snapshotDigest, irDigest, registryDigest, verifierDigest, policyDigest, optionSetDigest, selectedOptionId or null, eligibilityDigest, status (selected/semantic-defer/technical-refusal), reasonCodes, evidenceRefs, usage, executionAuthorization=false. No calibratedProbability, confidence or synthetic backend label. Serializing this into the old DecisionResponse is forbidden.

`ConsumerProposal`: new extracted handoff format, pins above plus consumerId, request/expected tree, proposalDigest, executionAuthorization=false. Exact T025 handoff/tree semantics must be explicitly mapped, never guessed. Consumer rejects unknown keys/versions, changed order, altered goals, forged prefixes, stale snapshots, mismatched tree, cross-consumer replay or tampered evidence chunks before prepare. It revalidates membership, source binding and target construction; a producer's hash alone is insufficient.

## Migration and rollback

Old fixtures, research modules and their packets remain byte unchanged. New modules do not import study/generator/labels or old result archives at runtime; use pure extracted logic with retained attribution. Compatibility tests assert old synthetic requests/responses and CLI defaults unchanged. Keep extracted runtime internal until governance approves any public schema/API and migration note. Feature off means exact legacy behavior. Rollback is disabling the new optional call path, not changing frozen semantics or purging historical records. No grant-store/runtime policy file is written.

The first supported value is a deterministic eligibility and plan-preparation assistant, not a general Laya replacement. Further domains require a finite operation language, acquisition/observation/execution contracts and independently reviewed negative controls. Full EN/ES understanding, probabilistic calibration and representative utility remain future separately gated work.
