# SPEC-022: Bounded M4 utility and cost follow-up

## Purpose and scope

The useful-speedup claim for SPEC-021 received G4 NO-GO on 2026-10-05. Six paired trials produced equivalent trees but a median serial/parallel total-wall ratio of 0.5581. Diagnose where cost is incurred and test a bounded follow-up. This is engineering measurement and a falsifiable utility protocol, not another runtime implementation or a retrospective change to the accepted result.

Only the existing 2–4 immutable ordinary-text A/M Git operation domain is admitted. No source-ref promotion, arbitrary repository code, paid model call, new host, remote effects or broader isolation claim. Positive acceleration is not required to finish this feature.

## Requirements and acceptance scenarios

### REQ-001 — Bind phase costs and the full safety boundary to immutable runtime inputs.

**SC-001:** Given a valid private Git fixture and serial/parallel treatment, when phase instrumentation runs, then phase totals reconcile to total wall time and no required verification or grant cost is omitted.

### REQ-002 — Prespecify a paired bounded utility comparison without selecting favourable outcomes.

**SC-002:** Given the frozen corpus, treatment order and declared limits, when all registered repetitions execute, then raw successful, rejected and infrastructure outcomes are retained; insufficient or invalid pairs make the affected block inconclusive.

### REQ-003 — Permit cost improvements only while preserving authorization, effects, recovery and verification.

**SC-003:** Given an optimization candidate and forged, stale, unknown or interrupted controls, when the candidate is compared with the frozen serial reference, then unsafe inputs are refused, admitted final trees agree, and every existing execution boundary remains enforced.

### REQ-004 — Separate experiment completion from utility acceptance and M4 closure.

**SC-004:** Given the registered results and SPEC-021 NO-GO, when a follow-up decision packet is prepared, then the packet reports direction and limits and preserves NO-GO until an explicit new founder decision; negative results complete the protocol.

## Scientific boundaries and compatibility

The hypothesis is that bounded workloads may amortize preparation overhead; it may fail. Total wall time includes input loading, evidence replay, preparation, grant issuance, private execution, verification and cleanup. Worker-only speedup is secondary. Tree agreement does not establish code correctness, semantic commutation or production safety. Preserve public schemas, grants, numerical budgets and every legacy analysis authorization denial. Do not change the current accepted observation to make results agree.
