# SPEC-071: Requirements quality checklist

A requirements-quality checklist, not a proof or approval.

- [ ] Every requirement is testable by a named procedure.
- [ ] Every REQ has at least one scenario in `assurance.json`.
- [ ] The paid-route refusal lists exact variable names and patterns.
- [ ] Key-source acceptance references `SUBSCRIPTION_KEY_SOURCES`, not a copy.
- [ ] Budget stop names are taken from `harness_hosts._BUDGET_STOPS`.
- [ ] The reward contains no LLM judgement.
- [ ] D4 and Wilson computations reuse frozen SPEC-069 code.
- [ ] The baseline interval and its source file are cited.
- [ ] route-changed comparison is reported, not hidden.
- [ ] Open decisions OD-1 and OD-2 name their blocking tasks.
- [ ] Exclusions cover Codex, promotion, traces and export.
- [ ] No claim exceeds the observed hosts, models and prompt set.
