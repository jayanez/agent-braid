## Selecting the D9 arm

The arm is baked into the built bytes, so all three hosts get it the same way.

| Arm | How to build | How to recognise it in `tools/list` |
|---|---|---|
| `per-kind` | build the candidate checkout as committed (`--arm final` today) | `analyze-work` `inputSchema` has `$defs` and `properties.request.oneOf` |
| `description-only` | in a disposable copy or worktree of the same commit run `python -m scripts.spec069_tool_schemas --delivery description-only`, then `scripts/build_native_plugin.py ... --allow-dirty`, or prebuild and pass `--plugin-dir` | `properties.request` is `{"oneOf": [{"type": "object"}, {"type": "array"}], "description": ...}` and there is no `$defs` |

- The description-only build is dirty by construction; record the sha256 of the generated
  `agent_braid/analyze_work_schema.py` and `provenance.json` `sourceDirty: true` with the
  arm. Only `per-kind` is committed (`tests/test_spec069_schema_delivery.py` fails
  otherwise).
- An environment variable was rejected as the switch: Codex forwards only a fixed list
  of variables to MCP servers unless the server entry declares more, and the plugin's
  `mcp.json` declares none, so the same build could silently serve the wrong arm there.
- The `description-only` arm is not the `baseline` arm: the baseline builds develop
  commit `8f63c606` (alpha.7 runtime); `description-only` builds the candidate runtime
  with only the request schema reverted, which is the D9 comparison.
- Expected fingerprints per arm and per tool (sha256 of the compact model-facing JSON:
  name, description, `inputSchema` after the `workspaceId` injection) can be printed from

## Host probe of the nested form (REQ-005 gate, per host)

Requested observations, per host (Claude Code, Codex, OpenCode) and per arm:

1. **Recording proxy.** Put a stdio recorder between the host and `launch plugin serve`
   (for example: in the disposable installed copy only, move `launch` to `launch.real`
   and install a wrapper that tees both directions to files under the run directory,
   then `exec`s `launch.real`; `plugin serve` does not run the package inventory check,
   `plugin doctor` would). Record per connection: the negotiated `protocolVersion`, the
   raw `tools/list` response line and its sha256, and the sha256 of the `result` object
   re-serialized canonically (sorted keys, compact) so the JSON-RPC `id` does not enter
   the comparison.
2. **Byte identity.** The `analyze-work` definition in `result` must be identical for
   every host connection of the same build; if two hosts negotiate different protocol
   versions, compare within each version and say so. Compare it with the fingerprint
   printed above.
3. **Host acceptance.** Record whether the host exposed `analyze-work` to the model at
   all (Claude Code: the tool appears in the `stream-json` init tool list; Codex: no
   `Failed to convert` MCP tool error in its log and the tool is callable; OpenCode: the
   tool is listed in the session), and whether a call made with
   `examples/analysis/file-edits.json` reaches the server with `request` as a JSON
   object, not a string (the proxy shows the `tools/call` arguments; a stringified object
   is the known MCP client failure for `$ref` and type-less schemas, for example
   anthropics/claude-code#18260). A host that hides or stringifies the nested form uses
   the description-only fallback as a declared limit.
4. **Eager or deferred loading.** Record whether the host sent the schema to the model
   at session start or only after a tool-search step (Claude Code defers MCP tool
   schemas until use), from the transcript.

## Source observations, not host evidence

Read on 2026-11-07 from `openai/codex` `main` (`codex-rs/tools/src/json_schema.rs` and
`json_schema/compaction.rs`): Codex keeps `$ref`, root `$defs`, `oneOf`, `anyOf`,
`required`, `enum`, `minItems`, `additionalProperties` and `description`; it drops
`pattern`, `minLength`, `uniqueItems`, `minimum`, `maximum`, `propertyNames` and
`title`; it rewrites `const` as a one-value `enum`; and above 5,000 bytes of its
normalized JSON it strips descriptions, then drops `$defs` (references become `{}`). The
`analyze-work` `inputSchema` here is about 3,850 bytes in that normalized form (aim and
git), so the threshold is not reached; `units` will add to it. Codex resolves only
`#/$defs/...` at the root, which is why the shared definitions sit at the top level. These
are readings of source code at one date; only the probe above observes the installed
host.
