## Finite procedure proposal

Use one root measurement coordinator. Begin before provisioning/data preparation;
end after cleanup, independent verification, workload export and a committed,
read-back run manifest. Write one terminal accounting receipt. Explicitly review
whether that final receipt is measurement apparatus outside the workload or a
single observed final phase. Later evidence packaging and GitHub publication
must not recursively enlarge the experiment interval. This is a proposal pending
contract review; neither option is silently adopted.

Prepare four disjoint CPU domains with raw start/end observations:

1. Root coordinator process.
2. Owned client descendants, excluding daemon services and worker containers.
3. Worker cgroup and descendants.
4. Daemon services, excluding containers.

Bind PID/birth/cgroup identities and reject resets, negative deltas, aliasing or
unknown overlap. VM-wide/helper child-tree counters are diagnostic aggregates,
not extra additive domains. Record memory current/peak/events, configured limits
and sample cadence separately. Snapshot before teardown; unobservable post-crash
values remain null with a concrete cause, never zero. Preserve all unsuccessful
attempts and expose residual/unallocated time instead of forcing reconciliation.
