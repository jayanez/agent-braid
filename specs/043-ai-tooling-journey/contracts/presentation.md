# Evidence presentation proposal

All views derive from the same versioned result envelope and owned artifact
inventory. Chat text is an explanation, not a proof or execution authority.

## Mandatory journey

Use an owned fixture with distinct independent-candidate, conflicting, conditional and unknown
cases. In each host: install/discover → analyze → inspect graph/evidence → prepare
→ identify absent grant and observe refusal → operator supplies existing exact
grant outside MCP → execute → verify → inspect interruption/recover control →
export. Keep execution opt-in and in fresh owned run directories. A synthetic
fixture is disclosed as synthetic.

The compact chat report gives: operation and input identity; decision with
assurance/observation boundary; conflict/dependency explanation; unknowns;
advisory order; authority needed; actual result/recovery state; evidence links.
Show private result versus source state, and verification versus code correctness.
No decorative scientific terminology or unobserved speedup claim.

## Graph and exports

Graph nodes identify operations; edges distinguish dependency, observed conflict,
conditional premise and unknown with labels plus color-independent styling.
Unknown means unresolved. Graph generation cannot invent an independence edge.
Retain full report/evidence identifiers and a visible legend/limits.

Export deterministic Markdown, SVG and standalone HTML from the typed envelope.
Use stable ordering and IDs, escape all text/attributes/URIs, forbid active source
HTML/scripts and remote resources, and bound input/node/output size. Offline HTML
may use reviewed self-contained presentation code; no telemetry or network calls.
SVG contains no scripts/foreign objects or file/remote references. Export only
operator-selected evidence; do not include secrets or arbitrary source content.

An export receipt binds source artifact hashes, formatter version, output hashes
and limits. Raw evidence remains separately available. Wrong/missing inputs,
invalid graph, stale evidence and overlarge output refuse instead of producing a
plausible report. A host's failure to render an image is recorded as unsupported
presentation; do not infer native MCP Apps support.
