## What to check

1. **Corpus construction.** Can tasks really be built from merged-PR regressions in this repository as specified, with a pre-fix base, a fail-to-pass test and a reference fix? Name concrete obstacles: tests that depend on the network or native hosts, or changes without tests. Is the H1 yield of ≥ 20 tasks that pass QA a fair, falsifiable statement?
2. **Lineage rule (OD-2).** Is the conservative merge rule (shared PR, spec, fixture base or unresolved relation) defined precisely enough that two people would produce the same lineages? Is it consistent with SPEC-049 D1–D3?
3. **Private split (OD-3, OD-7).** Do the storage outside the repository with only hashes committed, the 40/40/20 split by lineage and the ADR 0018 precedent prevent leakage into any optimizer? Check backup and loss handling, and whether a single lineage can end up straddling partitions.
4. **Task QA (REQ-006 to REQ-008, OD-4).** Is the cross-adversarial review fully specified? Claude and Codex review each task blind, critique each other's report, and the owner adjudicates. Is each review record labeled with model and version? Can REQ-008's "two distinct review records" be satisfied by two model records? Is model-reviewer collusion or shared blind spots addressed? Do the oracle-pass and exploit-fail checks catch a weak verifier?
5. **Infra controls (REQ-009 to REQ-011, OD-5).** Is the error taxonomy disjoint from agent failures? Check timeouts, quota stops, container crashes and "agent exceeded budget". Is the rerun cap (≤ 2) with the invalid-job rule (> 10 %, or a task losing all its trials) fixed before data? Do fresh run IDs prevent cache reuse?
6. **Cross-spec consistency.** SPEC-082 lists quota-stop as an infra error, while SPEC-083 SC-011 makes a quota-capped run `inconclusive`. Are the two compatible? Report any other conflict with SPEC-083 or SPEC-084.
7. **Traceability.** Do REQ, SC and procedure IDs match across `spec.md`, `assurance.json`, `tasks.md` and `validation-plan.md`? Are the dependencies between tasks acyclic?
