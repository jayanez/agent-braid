# M2 internal closure

## Scope

Assess the four published M2 exit criteria against a single frozen Git
candidate, an approved milestone-radar review, an internal clean-room
reproduction and two separate founder decisions. This is a closure protocol for
the bounded fixed-patch Git laboratory and consultative preparation prototype.

## Requirements and acceptance

- REQ-001: Bind every M2 closure input to a published frozen candidate ref and
  commit descending from the inspected remote `develop`, and record selected
  SHA-256; reproduce repository, contract, Spec Kit, scientific-control,
  replay, reduction and benchmark checks in a fresh clone and Python 3.12+
  environment. Record exact commands, exit codes, output and clean status.
- REQ-002: Verify each published exit criterion separately: immutable-fixture
  replay; bounded parallel-preparation recovery; fixed `tracked-tree-v1`
  observation with raw excluded differences; and conservative policies for
  destructive and external effects. Include negative and inconclusive controls.
- REQ-003: Require an explicitly approved M2 milestone-radar review and reject
  missing, pending or malformed radar evidence. Radar signals do not change
  contracts or authorize adoption.
- REQ-004: Check the registered SPEC-013 retest evidence and its reviewed input
  hashes without inferring a universal performance result. Do not rerun the
  expensive timed experiment unless its approved inputs changed and a new
  protocol is reviewed.
- REQ-005: Keep SPEC-016 as a private finite syntactic experiment. Its exhaustive
  oracle is regenerated and checked by the existing verifier, which shares the
  replay implementation; this is not independent implementation diversity.
  `uncertainPaths` block interchange. No semantic commutation, general
  confluence, execution authorization or public-contract promotion follows.
- REQ-006: Record separate founder scientific-review and M2 closure decisions
  against the reproduced candidate, disclose the founder conflict of interest,
  preserve `independent_validation: pending`, and reject any unreviewed
  post-freeze implementation change.

## Boundaries

The protocol may produce a passing internal reproduction while M2 stays open.
The accepted timing result is descriptive for two registered 30-pair batches;
both schedulers formed the same single wave. An isolated clone and the same
implementation do not constitute external or implementation-independent review.
No command in this specification authorizes agent execution, Git ref promotion,
publication, issue closure or release.
