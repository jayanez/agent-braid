## Delivered capability and boundary

Agent Braid now has a local, internal, opt-in deterministic verified-plan composition path. It acquires observed effects from owned synthetic Git repositories, interprets exact symbolic/controlled EN/ES text, evaluates all offered finite plans, chooses the lexically first minimum-operation-count valid plan, and carries complete bound evidence through Core API, an actual private ToolingService and a real stdlib MCP client subprocess. A model, Laya or Jev installation is not required by this path. It is not a general semantic predictor or a learned replacement for all typed boolean/choice/score decisions.

The original `decision-stdlib-v1` contract and synthetic reference backend remain separate and unchanged. Deterministic eligibility is not calibrated probability; no verified-plan record is converted into a legacy `DecisionResponse`. Producer selection, independent consumer reconstruction, native replay and read-only native preparation are different checks. A prepared manifest is not execution authority. Every advisory result retains `executionAuthorization: false`; no execution, recovery, grant or persistent-run capability is exposed by this lane.

### Exact supported domain

The current domain is `t024-eof-context-v1`, IR `t024-literal-program-v1`, grammar `t024-text-v1`, observation `t024-path-blob-projection-v1`, implementation `t024-eof-verifier-extracted-v1`. Wire formats include `s1-verified-request-v1`, `s1-acquired-snapshot-v1`, `s1-verified-plan-v1` and `s1-verified-consumer-proposal-v1`; see the exact [producer contract](contracts/verified-plan-v1.md) and [consumer contract](../031-system-one-integration/contracts/verified-plan-consumer-v1.md), not this synopsis, for every required field. The frozen contract's initial "not implemented" wording describes its drafting observation; later implementation receipts below establish only their bounded internal route, without adopting a public schema.

- Explicit immutable base/source commits in a coordinator-owned fixture root carrying `.owned-native-fixture`; a marker alone does not grant access. No private histories, arbitrary repositories or remote source URLs are admitted.
- LF UTF-8 text, regular tracked patch paths matching the bounded flat `.txt` vocabulary, 2–4 operations, at most 8 files, 2 paths per operation, 2 hunks per path and 128 patch lines per hunk. Initial/result file limits are 64/128 lines and 4,096/8,192 bytes. These bounds are not a general source-code editor domain.
- Exactly four offered options, with three plans of 0–6 operation IDs and one explicit null defer option. Repeated operations and empty plans are evaluated semantically. Unsupported/ambiguous/incomplete observations refuse; unknown is never completed by assumption.
- Retained trailing context permits a terminal-looking hunk to match before the current EOF. A last-line edit without retained trailing context remains EOF-constrained. BOF and literal diff prefixes retain their own checks; multi-file steps are staged atomically in the finite verifier.
- Exact EN/ES grammar round trips and equivalence to acquired state, not unrestricted prose understanding. Related translations/views are not independent observations.

Answered means a complete eligible offered plan was selected; semantic-defer means no offered action plan reaches the goal; refused means technical/domain/budget failure. No partial result is published as success. Equal-cost valid options remain eligible, while policy chooses the first ASCII identifier. Consumer proposals are usable only inside the original live request context; a rehashed or persisted proposal cannot manufacture freshness or an admission slot.
