## Exact increment and source ownership

New modules `agent_braid/system_one_verified_tooling.py` and `system_one_verified_stdio.py`, their two unittest modules, and this additive plan. The coordinator owns all changes serially. One minimal change to Core introduces a class-fixed consumer recipient and trusted `_prepare_native` method; its core-api defaults and existing signatures remain unchanged. The producer context additionally tracks locally owned subprocesses: if termination cannot be observed, it retains scratch and token ownership, refuses with unknown termination and requires explicit local investigation. Its former synchronous-only cleanup assumption cannot be applied to a new transport worker. No wire callable, dynamic module registry, context reconstruction, new default endpoint/catalog, global monkeypatch or optional ML dependency is introduced. The previous Core and producer source pins become historical in preserved source archives. All other pre-increment files remain byte-identical unless a concrete finding requires a separately recorded correction.

The service route invokes actual `ToolingService.invoke('prepare')` with its existing envelope/inventory/resource machinery. Its private instance uses a concrete bounded preparation runtime fixed to the reconstructed request/destination, passing the identical original Git budget and cancellation event to native `prepare_run`. It does not construct a policy execution plan or register a persistent run. Default ToolingService construction and catalogs are unchanged. The opt-in instance's prepare returns a complete native manifest through the existing evidence protocol, as required by this new internal consumer, rather than altering the legacy default policy-plan response.

The stdio route starts a real standard-library MCP client in a network-denied macOS subprocess. The parent hosts the service and retains the original trusted Core context; no trusted context, spent-budget reset or absolute monotonic timestamp is serialized. The child performs initialize, initialized, tools/list, prepare tools/call and resources/read, checks full artifacts and returns a terminal notification. Its private catalog exposes only the existing prepare name; it is not a stock SDK server or a public CLI registration. All Git/native work runs in the parent with the same aggregate budget. Child protocol work has explicit frame/byte/request/resource counters and observed termination. The parent independently reconstructs its owned evidence and requires exact returned content; a child hash/summary alone is insufficient. Child provenance is the pinned local implementation, not an external arbitrary host. Future host/server adoption is separate from this controlled harness.
